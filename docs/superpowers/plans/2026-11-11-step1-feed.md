# Step 1 → PCX Feed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PCX pulls Step 1's BOQ register on demand and turns long-lead items into requirements and *draft* revisions, with a PCX-side item→equipment-class crosswalk deciding which items qualify.

**Architecture:** A `Step1Client` (HTTP or fake) fetches the register; `services/step1_sync.py` applies it inside one DB transaction using the existing `create_requirement` / `add_revision` / `cancel_revision` functions, so audit, codes and `changed_fields` are not bypassed. `services/step1_items.py` owns the crosswalk. A new router `/api/integrations/step1` exposes it; two React pages sit on top. Step 1 itself is not modified.

**Tech Stack:** Python 3.13 · FastAPI · SQLAlchemy 2 · SQLite · httpx · pytest; React 19 · TypeScript strict · TanStack Query.

**Spec:** `docs/superpowers/specs/2026-11-11-step1-feed-design.md` (Task 1 amends it in four places; the plan wins where they differ).

## Global Constraints

- Sync creates **drafts only**. It never approves a revision, never edits an `APPROVED`/`SUPERSEDED` revision, never cancels a requirement.
- Quantities are `Decimal`, never `float`. Step 1 sends `boq_quantity` as a string such as `"6.000000"`.
- Unknown is `null`; nothing is coerced to `0`. Fields Step 1 does not know (duty, capacity, redundancy, install location, dates, budget) are never written by sync.
- Only `normalized_uom == "each"` is accepted (stored as `EA`). Any other unit → `VALIDATION` exception, nothing created or changed.
- A serialized class (`EquipmentClass.tracking == "SERIALIZED"`) needs a whole-number quantity > 0.
- Every query is tenant-scoped (`p.tenant_id`). Cross-tenant ids return 404. Supplier principals are blocked by `require_internal`.
- Roles: classify = ESTIMATOR, ENGINEERING, ADMIN. Sync = INTEGRATION, ADMIN. Read routes = any internal user.
- `PCX_STEP1_APP_PASSWORD` is never stored in the DB, logged, returned by an API, or included in an error message.
- Each project matches on `Project.procore_project_id == str(row["procore_project_id"])`, and on `procore_company_id` too when both sides have one.
- Exception `source` is `"STEP1"`; `subject_type` is `"step1_record"` (subject_id = Step 1 `inventory_record_id`) or `"requirement"`; `owner_role` is `"ESTIMATOR"`.
- Backend tests run from `backend/` with `python -m pytest -q`. The suite starts at **35 passed** and must never drop.
- Every commit message ends with the two attribution lines the session specifies (`Co-Authored-By: …` and `Claude-Session: …`).

## Review Focus

Inputs the spec implies but doesn't spell out (each has a test in the owning task):

1. **Postgres numeric text** — `"6.000000"` vs `"6"` vs `"6.0"` must hash identically, or every sync creates phantom revisions. *(Task 4)*
2. **Long or padded descriptions** — a 400-character or whitespace-padded description must become a trimmed title of ≤ 300 characters, not a database error. *(Task 4)*
3. **Malformed rows** — missing `item_id`, null or non-numeric `boq_quantity` must raise an exception for that record only; the run is `PARTIAL`, others still sync. *(Task 4)*
4. **Empty register for a project with existing links** — every linked record is reported dropped; nothing is cancelled; no crash. *(Task 5)*
5. **Component or unknown class in the crosswalk** — classifying an item `LLE` with a component class or a nonexistent class is rejected with 422 and changes nothing. *(Task 3)*
